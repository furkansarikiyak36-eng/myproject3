## Status and acceptance boundary

Group A has received a source-level implementation pass. This is **not** a claim that the features are complete or playable. Item catalogs, crop yield rules, terrain resource-yield rules, recipes, stations, discovery definitions, log mesh-family mappings, and per-level actor adapters still need authored values. The static pass checked balanced C++ delimiters/comment/string state in 21 unique source/header files and checked the expected declarations and code paths for the new inventory, survival, agriculture, terrain-yield, logistics and production contracts. These are lexical/source-invariant checks, not a compiler or runtime test.

## Shared contracts added or tightened

- **Inventory and identity:** item definitions cover weight, consumable effect, spoilage, animal feed, equipment, fuel, seeds, moisture input and medical treatment. Stack age, spoiled state and equipped slot are saved with stack state. Owned physical items cannot be consumed or equipped as ordinary stack units.
- **Shared time:** inventory age is preflighted and advanced with the world coordinator fixed step, not an independent actor frame timer. The coordinator captures inventory state for compensating rollback.
- **Survival:** health/food/water, clothing insulation, shelter protection, rest, active afflictions, weather and heat-source exposure share the survival profile and revision checks.
- **Crop/animal stock:** configured crop yield and animal-product collection now create inventory stack outputs only after capacity preflight; feeding/watering consume inventory inputs. This is logical inventory output, not yet a physical pickup actor.
- **Resource/production flow:** mining yield becomes an ownership-ledger stack, then can transfer to production stock with quantity and a receipt. Operation retries must reuse the same operation ID and payload.
- **Route costs:** base cost stays authored; contextual terms are explicit and finite/range-checked. Missing physical mass/weather adapters are not guessed.
- **Save compatibility:** save schema is now v21. v19→v20 initializes new inventory-aging/equipment, rest/affliction and discovery-unlock fields to neutral defaults. v20→v21 initializes new terrain resource/yield receipts, cargo cost-context fields, production-intake receipt semantics and recipe unlock fields to legacy-safe defaults.
- **Initialization and failure policy:** `RegisterSolidCell` admits only a new, unexcavated, material-backed logical cell within configured depth/cell limits. Record-only discovery cannot create a record for an ID with authored unlock prerequisites; those requests must use the radius/equipment-checked `TryDiscover` path. Unsupported mesh cuts, ambiguous authored definitions, invalid revisions, capacity failures and missing resource rules reject the operation rather than fabricating a result.

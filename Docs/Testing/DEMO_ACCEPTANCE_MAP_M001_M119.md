# 119-Mechanic Integrated Demo Acceptance Map

**Purpose:** final integrated demo layout and evidence contract. This is a planned acceptance map, not a claim that all 119 mechanics currently pass. The canonical IDs and names below are copied from `MECHANIC_REGISTRY_119.md`; do not renumber or infer completion from inclusion here.

## Seven deliberately designed zones

1. **Z1 — Resource yard:** trees/logs, processing benches, loose stone/sticks, inventory and recipes. Demonstrates physical lifecycle prerequisites without unrelated clutter.
2. **Z2 — Construction yard:** foundations, wood/stone/stick assemblies, anchors, supports, bridges, walls, damage and removal. Every attachment has a visible anchor/support reason.
3. **Z3 — Terrain pocket:** a bounded excavation area with permitted depth layers, a tunnel/underground room, a blocked-depth example and a restore marker.
4. **Z4 — Farmstead:** soil plots, crop stages, water/moisture source, animal pen, feed storage and product collection.
5. **Z5 — Raid settlement:** warning point, attack approach, defensive structures, damage targets, repair/salvage area and a repelled/failed outcome.
6. **Z6 — Logistics / production site:** source storage, route nodes, cargo destination, production stations, queue/storage capacity and a visible blocked-output example.
7. **Z7 — Survival / exploration route:** weather-exposed segment, sheltered stop, food/water/rest options, equipment comparison, environmental ruin/discovery and save/load marker.

## Required evidence per mechanic

For each row, the final demo evidence must record: (1) setup and prerequisites, (2) valid action and expected state/result, (3) invalid action and expected rejection with no partial mutation, (4) retry/idempotency result where relevant, (5) cross-system consequence, (6) save/load expectation, and (7) capture/log reference. A screenshot alone is not proof of hidden state or atomicity.

## Global hard gates

- A rejected prerequisite leaves actor, graph, inventory, terrain, event ledger and logical time unchanged.
- Every physical resource has one authoritative owner at a time; pickup, carry, storage, cargo, processing and consumption cannot duplicate it.
- A groove is rejected on a whole log; grounded/armed traps require the correct placement state; overlap never substitutes for a committed anchor.
- Structure removal uses a deterministic leaf-first dependency plan; no orphaned child links.
- Terrain edits remain within authored layer/depth and operation bounds; collision/navigation/visual adapters must agree with logical state.
- Every simulation domain advances from the same fixed-step coordinator; failed preflight means no step advances.
- Production and cargo report blockers instead of silently dropping work or resources.
- Save/load restores the same logical clock, ownership, terrain records, crop/animal states, survival, production, cargo and threat schedule; physical actors, graph reconstruction and inventory component persistence need separate proof.
- Registry statuses stay `unreviewed` until source review and then engine/runtime evidence are separately recorded. No UBT/UHT/Editor/PIE claim is inferred from source review.
